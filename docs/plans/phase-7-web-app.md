## A. Architecture decisions (settled 2026-11-26, D117–D123)

- [x] **A1. Where pages get their data.** **Settled → D117** (Ben, 2026-11-26). Recommended: Inertia props for the page and its content (a model's metadata and Markdown, a topic page, the methods, the changelog, the user and their settings, the shared `status` and `today`); the browser fetches `/api/v2` for data (weather, model runs, risk, tiles, climate). D57 made the frontend the API's first client, so a number on a page is the API's number; the map and charts change with the reader's settings without a page visit; ETags and the API's caching come for free. One typed client (`lib/api.ts`) over `@/types/api`: the envelope, `meta.warnings` shown in the API's words, errors, `Retry-After`, an abort on a superseded request. Alternative: props for everything (WISP 3's way), which means a page visit per setting change and a second path to every number.
- [x] **A2. URL state.** **Settled → D118** (Ben, 2026-11-26), not as recommended: the address bar stays on the plain path and a Share button gives the link with the settings (provisional). Recommended was: the view lives in the query string (frontend.md: `?layer=…&time=…&at=…&z=…`), through one helper that maps a typed state object to and from the query, writing with `history.replaceState` as settings change (no Inertia visit, so the map isn't torn down) and `pushState` only for a change a reader would go Back from (another layer, another site). Shared links reproduce the view; defaults are left out of the URL.
- [x] **A3. The map.** **Settled → D119** (Ben, 2026-11-26). Recommended: one `DataMap` on MapLibre from WISP 3's core, with our data tiles as a `raster-dem` source (`encoding: "custom"`, the TileJSON's factors) colored by a `color-relief` layer from `/palettes`, so a palette or scale change recolors on the GPU with no request; the value under the pointer decoded from the same tile's pixels (fetched once, kept); OpenFreeMap's light style with its labels above the data; WISP 3's overlays; Save image from late-blight-db. Zoom past 8 enlarges zoom 8 (the API's tiles stop there). Risk: `color-relief` is new in MapLibre and untried here; a custom WebGL layer is the fallback (M more).
- [x] **A4. Saved sites, groups and preferences in the browser, then synced.** **Settled → D120** (Ben, 2026-11-26). Recommended: one versioned store in `localStorage` (`lib/storage`), shaped as the Django models will be: sites keyed by coordinates (F1), groups, and preferences at three levels (all sites, group, site) holding shown crops and models, map view and chart defaults, with groups' choices joined by union (F3, F11, F12). Signed in, the server is the source and the browser a cache; at first sign-in the browser's sites merge into the account by coordinates, and nothing is lost. Up to 50 sites (F4).
- [x] **A5. How WISP 3's base is ported.** **Settled → D121** (Ben, 2026-11-26). Recommended: copied into the same paths under `frontend/lib/` (so later fixes in either app carry across by diff), with WISP's route helpers replaced by a small `lib/routes.ts` generated by `bin/types` from Django's URL names (the props types already come from there), and its tests ported with each file. A note at the top of each ported file names its WISP 3 source.
- [x] **A6. Accounts.** **Settled → D122** (Ben, 2026-11-26). Recommended: django-allauth with login by emailed code and link (allauth's "login by code"), no passwords (architecture.md §8), our own Svelte pages over allauth's headless API rather than its Django templates, sessions as now (CSRF as now). Settings: units, beta models, service updates, alerts. Allauth's admin covers user management.
- [x] **A7. Email.** **Settled → D123** (Ben, 2026-11-26). Recommended: Django templates (HTML and text) in WISP 3's layout, sent by Procrastinate jobs; one daily digest per user at a chosen hour and event alerts (a model reaching a level, a forecast frost) at most once per event; unsubscribe by signed link. Ben: `agweather@cals.wisc.edu` through Amazon SES, as WISP 3 (TODO.md); mail on a queue and worker of its own.

## Track 2 in detail: the map explorer `/map` (planned 2026-11-26, for Ben)
